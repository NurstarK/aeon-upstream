# ISS-002 — agent-buzz blocked on missing XAI_API_KEY

## Summary
agent-buzz produces a curated read of AI-agent tweets, clustered and scored by
engagement (likes/retweets/replies), with each item linked by its
`x.com/.../status/<id>` URL. All three fetch tiers in the skill's fallback chain
depend, for a usable product, on tweet-level metadata:

1. `curl` → X.AI x_search — needs `XAI_API_KEY`.
2. WebFetch → X.AI endpoint — needs `XAI_API_KEY`.
3. WebSearch forced-fresh — works without auth but returns news articles and
   roundups, **not** tweets with engagement counts or verifiable fresh status links.

With `XAI_API_KEY` unset, only tier 3 runs, and it cannot satisfy step 3 (signal
scoring) or the step 7 output format without fabricating handles, counts, and
status IDs — which the skill and CLAUDE.md forbid.

## Impact
Skill emits ERROR every scheduled run (daily 17:30). No curated feed is delivered.
Distinct from the heartbeat "staleness" signal: cron-state records exit-success even
on ERROR, so the skill looks healthy at the scheduler level while producing no product.

## Fix options
1. **Preferred:** set the `XAI_API_KEY` repository secret → restores tier 1/2.
2. If no key is available: relax the skill spec so a degraded, clearly-labeled
   news-digest mode is an acceptable `OK` output (no fabricated tweet metadata),
   or make agent-buzz emit `EMPTY`/disabled rather than daily ERROR when the key
   is absent.
